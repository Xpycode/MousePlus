## What shipped

### New files
- **`Utilities/KeyCodeNames.swift`** — `kVK_*` → label map, mouse-button friendly names,
  and a `TriggerBinding` extension (`displayString` / `mode` / `withMode`).
- **`Services/TriggerRecorderService.swift`** — one-shot "press the trigger you want"
  recorder (`@MainActor @Observable`). Captures the next `.keyDown` / `.otherMouseDown`
  as a candidate `TriggerBinding`, swallows it locally, Esc cancels, and arms a **4s
  timeout → `.timedOut`** that surfaces the vendor-interception warning.
- **`Views/TriggersSettingsView.swift`** — two binding rows (keyboard + mouse), each with
  current-binding display, Record/Clear, and a segmented hold-release / tap-toggle picker;
  Accessibility permission banner; interception warning; debounced persist + live apply.

### Edits
- **`SettingsView.swift`** — replaced the dead "Hotkey" tab with **"Triggers"**
  (`cursorarrow.click.2`); trimmed General's misleading hold/tap `@AppStorage` toggles
  (mode is per-binding now); window height 420 → 460.
- **`Configuration.swift`** — `TriggersConfig: Equatable` (needed for `.onChange`).
- **`MousePlusApp.swift`** — **the wiring-bug fix**: `setupTriggers()` ignored persisted
  config (`start(config: .default)`) and `loadConfiguration()` never pushed `triggers`
  into the live `TriggerService`, so the app always booted the hardcoded F5+middle default.
  Now starts from `configuration.triggers`, and the load completion + new
  `AppDelegate.applyTriggers` hook push saved/edited triggers into the running monitors
  (live rebind with no restart).

## Bugs found & fixed during verification
- **Recorder captured the `.function` flag.** macOS sets `.function` on every F-row/arrow
  key; the recorder stored it (`modifiers: 8388608` for F4), which works for physical
  presses but breaks the premium "map a mouse button → F-key" path (Logi Options+/
  BetterMouse-injected keycodes omit `.function`). Fixed: strip to chord modifiers
  (⌃⌥⇧⌘) only at record time. Matches why the F5 default uses `modifiers: 0`.
- **Identify Input window no longer minimizable.** A recent session set
  `w.level = .floating`; AppKit disables the minimize button above `.normal` level.
  Reverted to `.normal`.
- **No reliable way into Settings on M1 Max** (menu-bar icon invisible bug). Added a
  temporary **"Settings…" button** to the auto-opened Identify Input window
  (`InputRecorderView` → container → controller → `AppDelegate.showSettings`).

## Process gotchas (not code)
- **Launched a stale binary repeatedly.** `find DerivedData/MousePlus-*/… | head -1`
  is nondeterministic and grabbed a stale **ad-hoc** build (hours old, permission lost)
  instead of the fresh one. The correct build (`MousePlus-hbra…`) is properly signed with
  the stable "Apple Development: GREGOR MÜLLER (H56HM4MMZS)" cert → TCC persists across
  rebuilds. **Lesson: always launch `xcodebuild -showBuildSettings → TARGET_BUILD_DIR`,
  never `find | head`.** Deleted the two stale DerivedData dirs (`clnt`, `dvuk`).
- xcconfigs live in `01_Project/Config/` (Shared/Debug/Release/Debug.local/Tests), not
  `01_Project/` root.
