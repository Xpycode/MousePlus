## Decisions
- **Settings hotkey = ⌥⌘, not plain ⌘,.** `NSEvent.addGlobalMonitorForEvents` is observe-only (doesn't
  consume), so a global `⌘,` watcher would open MousePlus Settings *on top of* the frontmost app's own
  `⌘,` Preferences. `⌥⌘,` avoids that collision; rebindable in Settings ▸ Triggers.
- **`TriggersConfig` made decode-tolerant.** It relied on synthesized `Codable`, which throws
  `keyNotFound` on any missing key — so naively adding `openSettings` would have broken every existing
  config (the same synthesized-Codable data-loss trap the menu-editor pass fought). Custom
  `init(from:)` with per-field defaults fixes it and back-fills the hotkey for existing users.
- **Reach-Settings-from-the-HUD is the real want** → proposed a new `ActionType.openSettings` (a Settings
  wedge you can drop into the ring via the editor). Not yet built.
