### Discovered — pre-existing bugs found while debugging

- **Modifier flag bug.** `HotkeyConfig.default` claimed `1 << 20` was "Control" — it's actually `.command`. So the *real* default trigger was Cmd+Space, hence the Spotlight/Alfred/Raycast collision. The "Ctrl+Space" symptom was a misleading comment all along. Replaced with `keyCode: 46 /* M */, modifiers: (1 << 20) | (1 << 18) /* Cmd | Ctrl */` as a non-colliding test default; W4 deletes this entirely per D1.
- **`INFOPLIST_KEY_*` whitelist.** Xcode's auto-mapping from `INFOPLIST_KEY_<KeyName>` xcconfig entries to generated Info.plist only handles a curated set of "blessed" keys. Custom TCC strings like `NSAccessibilityUsageDescription` silently drop — they appear in `xcodebuild -showBuildSettings` but not in the bundle. Forced switch to a static Info.plist.
- **Synced-folder Info.plist duplication.** `fileSystemSynchronizedGroups` (Xcode 16's automatic folder→target inclusion) auto-bundles every file as a resource — including the Info.plist if it lives inside a synced folder. Resulted in `Contents/Info.plist` *and* `Contents/Resources/Info.plist`. Fixed by placing Info.plist at `01_Project/Info.plist`, outside any synced group.
- **Key-repeat ring stacking.** `keyDown` repeats at the system key-repeat rate (~30 Hz) for as long as the key is held. Without a guard, `showRing()` ran every tick and created a fresh `NSPanel` + `NSHostingView` each time — visible as two rings stacked with slight offset. Guarded with `controller.isVisible`.

### Decisions Made

- D1, D2, D3 (see decisions.md "Trigger Model" entry for the unified write-up)
- Static Info.plist over auto-generated (forced by `INFOPLIST_KEY_*` whitelist limitation; future-proof for any future custom plist key)
- Non-sandboxed for v1 (`com.apple.security.app-sandbox = false`) — global event monitors don't survive sandbox without temporary entitlements Apple won't grant. Aligns with GPLv3 + direct distribution path decided 2026-04-26.

### Discovered during W2

- **`AXIsProcessTrusted()` discrepancy by launch method.** Direct binary launch (`/path/to/.app/Contents/MacOS/Binary`) reports cached `true` even when the actual TCC grant is stale. `open --stdout file ...` (LaunchServices) reports the live `false`. Diagnostic-capture launches must use `open --stdout`.
- **Ad-hoc signing × TCC.** Every rebuild produced a different cdhash, invalidating the Accessibility grant silently. Symptom: `AXIsProcessTrusted=true` but no events flow. Fixed by switching Debug to **Apple Development cert** + Team `H56HM4MMZS` in `Debug.xcconfig`. Saved as memory: `tcc-adhoc-signing` + `apple-developer` references.
- **`OnboardingWindowController` swallowed exception.** `w.collectionBehavior = [.canJoinAllSpaces, .moveToActiveSpace]` — those flags are mutually exclusive. Synchronous call path silently deadlocked; only surfaced when I dispatched the call async. Fixed by dropping `.canJoinAllSpaces`. Was dead code in W1 (we never went through onboarding because permission was already granted).
- **xcconfig `CODE_SIGN_IDENTITY = "Apple Development"`** doesn't match Apple Dev certs by name on macOS — Xcode resolves it to legacy "Mac Development". Use the cert SHA-1 instead.
- **`stdout` is block-buffered when redirected to a file.** Set `setvbuf(stdout, nil, _IONBF, 0)` in `MousePlusApp.init()` for diagnostic captures (later removed; only needed during debugging).

## Notes

- Permissions plumbing follows the standard macOS utility pattern (Karabiner / Rectangle / AltTab): `AXIsProcessTrustedWithOptions(prompt: true)` + 0.5s polling. There is no notification API for grant changes — polling is the only option.
- Diagnostic prints were used to trace the ⌘⌃M event path (`startMonitoring` config logging + per-event `keyMatch`/`modsMatch` flags + PRESSED/RELEASED markers). Removed once the flow was confirmed working. Pattern worth re-using for the mouse-button monitor in W3.
- The temporary ⌘⌃M default is **not** the shipping config. Per D1, v1 ships with no trigger configured and forces onboarding to pick one.
