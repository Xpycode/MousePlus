## Design idea logged (not yet a decision) — "drill-down / marking-menu" ring navigation
While using the working snap feature, user noted the **third (outer) ring** is large and far
from center, so drilling in + selecting feels cumbersome. Proposed alternative to the static
3-ring concentric layout:

- Show **one active ring** at a time.
- Selecting a wedge → the current ring recedes/"slightly vanishes" and a **new ring appears
  localized around the wedge just chosen**; repeat for deeper levels.
- Payoff: the next command is **always ~the same distance and direction away** from where the
  cursor just acted → consistent gesture rhythm / muscle memory (cf. Maya/Blender marking
  menus, Alias radial breadcrumbs).
- Trade-off: loses the concentric design's "see two levels at once"; gains shorter travel +
  consistency. Directly targets the observed outer-ring friction.

Captured here + flagged in PROJECT_STATE (Ring-UI track) as an open design question. Not
scheduled; revisit before investing further in deep outer-arc interactions.

### Follow-on idea — selectable interaction/layout model (umbrella)
User then broadened it: don't pick one style — make the **interaction model a user choice**.
Candidates: (1) concentric 3-ring [current], (2) drill-down/marking-menu [above],
(3) **Stream Deck-style grid** (fixed rows×cols of labeled buttons, learned by position;
likely a different *summon* model — fixed/persistent vs. at-cursor), (4) a novel model after
research.

**Architecture read (logged so we don't over-build):** the data model
(`RingMenuItem`/`Configuration`) is already layout-agnostic; layout code lives in
`RingMenuView` (render) + `RadialGeometry` (hit-test) + `commitActive`/`expand`
(`RingViewModel`). A `MenuStyle`/`InteractionModel` protocol could let those plug in,
selected in Settings. **But** extracting that seam now — across models that don't exist —
would guess the interface wrong (grid wants pages/columns; drill-down wants a nav stack;
ring wants angular spans). **Recommended sequencing:** finish more action features, then
build the **drill-down model as a second renderer behind a flag** (the second layout reveals
the real protocol); Stream Deck + researched models drop in afterward; ship the "choose your
model" setting only once ≥2 exist. Not scheduled.
