### Discovered
- The original `Config/PointerActions.entitlements` file was effectively empty (`<dict/>`). This is almost certainly **part of the hotkey blocker** from January — without an Accessibility entitlement entry, the system never prompts the user to grant the permission that NSEvent global monitor needs.
- `01_Project/MousePlus.xcodeproj/xcshareddata/xcschemes/` was empty — Xcode hadn't created a shared scheme yet. The implicit scheme regenerated automatically on first build.
- Project was not previously a git repo. Now is, on `main`, tracking `origin/main` at github.com/Xpycode/MousePlus.
- Codebase uses Xcode 16's PBXFileSystemSynchronizedRootGroup (buildable folders) — files auto-sync from disk, which made the rename much cleaner than legacy pbxproj file references would have been.
- **The `Config/` folder was at the wrong level the whole time**: pbxproj expected it at `01_Project/Config/`, but it lived at workspace root. Xcode IDE silently resolved it via xcuserdata, so the January "build is clean" report was technically true *in Xcode* but the project would have failed under any CLI build (xcodebuild, fastlane, GitHub Actions). Fixed now.
- **GPLv3 has a known conflict with Apple App Store distribution** (the VLC-on-iOS precedent). If MAS becomes the goal, will need to either re-license to MPL-2.0 / Apache / MIT, or add a Mac Mouse Fix-style App Store exception clause. Logged in commit message, in licensing memory, and noted here so it doesn't get lost.
